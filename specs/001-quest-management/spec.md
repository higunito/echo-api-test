# Feature Specification: クエスト管理の基本機能

**Feature Branch**: `001-quest-management`

**Created**: 2026-10-11

**Status**: Draft

**Input**: User description: "クエスト管理の基本機能: ギルドがクエストを登録・一覧・詳細表示でき、冒険者が受注・完了報告できる"

## Clarifications

### Session 2026-10-11

- Q: 本機能では、ギルド職員と冒険者をどうやって区別・識別しますか？ → A: 認証なし。画面上で役割（職員／冒険者）と操作する冒険者を選択し、その冒険者として操作する
- Q: 期限を過ぎても誰も受注していないクエストは、どう扱いますか？ → A: 状態は「募集中」のまま、一覧・詳細に「期限切れ」表示を付けて受注のみ拒否する。一覧には「期限切れを除く」絞り込みを用意する
- Q: クエスト一覧は件数が増えたとき、どう表示しますか？ → A: ページ番号方式、1 ページ 20 件。総件数と総ページ数も表示する

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ギルドがクエストを登録する (Priority: P1)

ギルド職員は、依頼内容（タイトル・説明・報酬・期限）を入力してクエストを登録する。
登録されたクエストは「募集中」として公開される。

**Why this priority**: クエストが存在しなければ受注も完了報告も成立しない。全機能の起点となる。

**Independent Test**: クエストを登録し、登録内容がそのまま保存され「募集中」状態になっていることを
確認できれば単独で価値を検証できる。

**Acceptance Scenarios**:

1. **Given** ギルド職員がクエスト登録画面を開いている, **When** タイトル・説明・報酬・期限を入力して登録する,
   **Then** クエストが「募集中」状態で保存され、登録完了が表示される
2. **Given** ギルド職員がクエスト登録画面を開いている, **When** タイトルを空のまま登録する,
   **Then** 登録は拒否され、タイトルが必須である旨が表示される
3. **Given** ギルド職員がクエスト登録画面を開いている, **When** 報酬に負の値を入力して登録する,
   **Then** 登録は拒否され、報酬は 0 以上である旨が表示される

---

### User Story 2 - クエストを一覧・詳細表示する (Priority: P1)

ギルド職員と冒険者は、登録済みクエストの一覧を閲覧し、状態で絞り込み、
個別クエストの詳細（説明・報酬・期限・状態・受注者）を確認できる。

**Why this priority**: 冒険者が受注するクエストを選ぶため、またギルドが進捗を把握するために必須。

**Independent Test**: 複数のクエストを用意し、一覧表示・状態絞り込み・詳細表示がそれぞれ
正しい内容を返すことを確認する。

**Acceptance Scenarios**:

1. **Given** 募集中・受注済・完了のクエストがそれぞれ存在する, **When** 一覧を開く,
   **Then** クエストがタイトル・報酬・期限・状態とともに新しい順に、1 ページ 20 件で表示され、
   総件数と総ページ数が示される
2. **Given** 複数状態のクエストが存在する, **When** 「募集中」で絞り込む,
   **Then** 募集中のクエストのみが表示される
3. **Given** クエストが存在する, **When** その詳細を開く,
   **Then** 説明・報酬・期限・状態・受注者（受注済みの場合）が表示される
4. **Given** 期限を過ぎた募集中のクエストがある, **When** 一覧を開く,
   **Then** そのクエストに「期限切れ」の表示が付き、「期限切れを除く」で絞り込むと表示されない
5. **Given** 存在しないクエストを指定する, **When** 詳細を開く,
   **Then** クエストが見つからない旨が表示される

---

### User Story 3 - 冒険者がクエストを受注する (Priority: P2)

冒険者は、募集中のクエストを選んで受注する。受注されたクエストは「受注済」となり、
他の冒険者は受注できなくなる。

**Why this priority**: アプリの中心的な価値だが、登録・閲覧が先に成立している必要がある。

**Independent Test**: 募集中のクエストを冒険者 A が受注し、状態が「受注済」・受注者が A になること、
冒険者 B が同じクエストを受注できないことを確認する。

**Acceptance Scenarios**:

1. **Given** 募集中のクエストがある, **When** 冒険者 A が受注する,
   **Then** クエストは「受注済」になり、受注者として A が記録される
2. **Given** 冒険者 A が受注済のクエストがある, **When** 冒険者 B が同じクエストを受注しようとする,
   **Then** 受注は拒否され、既に受注されている旨が表示される
3. **Given** 期限を過ぎた募集中のクエストがある, **When** 冒険者が受注しようとする,
   **Then** 受注は拒否され、期限切れである旨が表示される

---

### User Story 4 - 冒険者が完了報告する (Priority: P2)

クエストを受注した冒険者は、依頼を達成したら完了報告を行う。報告されたクエストは「完了」となる。

**Why this priority**: 受注から完了までのライフサイクルを閉じるために必要。

**Independent Test**: 受注済のクエストを受注者本人が完了報告し、状態が「完了」になること、
受注者以外は報告できないことを確認する。

**Acceptance Scenarios**:

1. **Given** 冒険者 A が受注済のクエストがある, **When** A が完了報告する,
   **Then** クエストは「完了」になり、完了日時が記録される
2. **Given** 冒険者 A が受注済のクエストがある, **When** 冒険者 B が完了報告しようとする,
   **Then** 報告は拒否され、受注者のみ報告できる旨が表示される
3. **Given** 募集中のクエストがある, **When** 冒険者が完了報告しようとする,
   **Then** 報告は拒否され、受注されていない旨が表示される

---

### Edge Cases

- 2 人の冒険者がほぼ同時に同じクエストを受注した場合、成功するのは 1 人のみで、もう 1 人には
  既に受注されている旨が表示される。
- 既に「完了」のクエストを再度受注・完了報告しようとした場合は拒否される。
- 期限を過去の日付にしてクエストを登録しようとした場合は拒否される。
- 受注済のクエストが期限を過ぎても、受注者は完了報告できる（期限切れ判定は受注時のみ）。
- 一覧にクエストが 1 件もない場合、空である旨が表示される。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST ギルド職員がタイトル・説明・報酬・期限を指定してクエストを登録できること
- **FR-002**: System MUST タイトル（1〜100 文字）を必須とし、空や上限超過の登録を拒否すること
- **FR-003**: System MUST 報酬を 0 以上の整数（ゴールド）として受け付け、負の値を拒否すること
- **FR-004**: System MUST 期限を任意項目とし、指定する場合は登録時点より未来の日時のみ受け付けること
- **FR-005**: System MUST 新規登録したクエストを「募集中」状態にすること
- **FR-006**: Users MUST be able to クエスト一覧を登録日時の新しい順に閲覧し、状態（募集中・受注済・完了）で絞り込めること
- **FR-006a**: System MUST 一覧をページ番号方式で 1 ページ 20 件ずつ表示し、総件数と総ページ数を示すこと。
  絞り込み条件はページ移動後も維持し、範囲外のページ番号を指定した場合は空の結果を返すこと
- **FR-007**: Users MUST be able to クエストの詳細（説明・報酬・期限・状態・受注者・完了日時）を閲覧できること
- **FR-007a**: System MUST 期限を過ぎた「募集中」クエストを一覧・詳細で「期限切れ」と表示すること。
  期限切れは保存される状態ではなく、期限と現在時刻から都度判定する
- **FR-007b**: Users MUST be able to 一覧を「期限切れを除く」で絞り込めること（状態絞り込みと併用可）
- **FR-008**: System MUST 冒険者が「募集中」かつ期限内のクエストのみ受注できるようにし、受注時に受注者と受注日時を記録すること
- **FR-009**: System MUST 1 つのクエストを同時に複数の冒険者が受注できないことを保証すること（同時操作時も含む）
- **FR-010**: System MUST 「受注済」クエストの受注者本人のみが完了報告でき、報告時に状態を「完了」にして完了日時を記録すること
- **FR-011**: System MUST 状態遷移を「募集中 → 受注済 → 完了」の順に限定し、それ以外の遷移を拒否すること
- **FR-012**: System MUST 操作が拒否された場合、利用者が理由を理解できるメッセージを表示すること
- **FR-013**: System MUST 冒険者の一覧を保持し、利用者が画面上で役割（ギルド職員／冒険者）と
  操作する冒険者を選択できること。受注・完了報告は選択された冒険者の操作として扱う（認証は行わない）

### Key Entities

- **クエスト (Quest)**: ギルドが公開する依頼。タイトル、説明、報酬（ゴールド）、期限（任意）、状態
  （募集中・受注済・完了）、受注者、登録日時、受注日時、完了日時を持つ。受注者は 0〜1 人の冒険者。
- **冒険者 (Adventurer)**: クエストを受注・完了報告する人物。名前を持ち、複数のクエストを受注できる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ギルド職員が 1 件のクエストを 1 分以内に登録できる
- **SC-002**: 冒険者が一覧を開いてから目的のクエストを受注するまでを 3 操作以内で完了できる
- **SC-003**: クエストが 1,000 件ある状態でも、一覧・詳細が 1 秒以内に表示される
- **SC-004**: 同一クエストへの同時受注を 100 回試行しても、二重受注が 0 件である
- **SC-005**: 不正な操作（期限切れ受注・他人の完了報告など）がすべて拒否され、理由が表示される

## Assumptions

- 本機能ではログイン・認証は扱わない。ギルド職員と冒険者の区別、および操作する冒険者は
  画面上で選択する簡易方式とし、認証は将来の機能とする。
- 冒険者はあらかじめ用意されたデータ（初期データ）を利用し、冒険者の登録・編集は別機能
  （冒険者の登録と管理）で扱う。
- ランク制限・同時受注数上限などの受注ルールは別機能（クエスト受注ルール）で扱い、本機能では
  冒険者は複数のクエストを制限なく受注できる。
- クエストの編集・削除、受注の取り消し、ギルドによる完了承認、報酬の支払い処理は対象外とする。
- 報酬の通貨単位はゴールド（整数）のみとする。
- 日時はすべて単一のタイムゾーン（日本時間）で扱う。
